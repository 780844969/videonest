# 拾影 VideoNest：视频下载功能总结

截至 2026-11-11，项目已完成 B站、抖音、快手单个公开视频的本地下载流程。用户粘贴链接或分享文案，选择源站提供的画质，下载完成后保存文件。三个平台均不要求用户提供 Cookie。当前版本无需数据库，没有接入支付。

## 三个平台如何获取视频

| 平台 | 最终实现 | 已验证的用户作品 |
| --- | --- | --- |
| B站 | 直接调用 yt-dlp 内置提取器；音视频分轨时由 FFmpeg 合并 | 360P MP4，12,912,256 字节；另识别到 480P、720P、1080P，未对该作品逐档下载 |
| 抖音 | 后端建立临时匿名访客会话，从移动分享页读取与目标作品 ID 匹配的详情，交给 yt-dlp 处理 | 1080P MP4，112,958,277 字节，约 4 分 51 秒 |
| 快手 | 从官方移动分享页读取作品清单，校验分享 ID 后提取实际媒体流 | 720P MP4，1,484,989 字节，8.4 秒 |

三条样例均已实际下载并通过 FFmpeg 解码。抖音、快手也通过了浏览器从粘贴链接到保存附件的测试。结论来自 [B站实测](USER-LINKS-TEST.md) 和 [11 月 1 日两平台复验](ANONYMOUS-DOWNLOAD.md)，不代表所有作品或今后的平台版本均可用。

## 设计取舍

FastAPI 接收任务，前端轮询进度；独立 Python 进程负责解析、下载和转换，所以耗时任务可以取消或超时终止。平台适配集中在获取媒体信息这一步，三个平台共用 yt-dlp 下载、格式选择和 FFmpeg 处理流程。后端自动获得的访客信息仅用于当前请求流程，不读取个人浏览器登录信息。

开发时遇到两类容易误判的问题：抖音解析器提示缺少 Cookie，但同一作品可匿名播放；快手桌面页返回 HTTP 200，却可能只有页面框架。最终的判断依据是**作品 ID 匹配、有可下载的媒体流、文件能完整解码**，而非页面状态码或一次解析成功。

## 运行与维护

- 按 [README](../README.md) 安装环境并启动本地服务。任务状态保存在内存中，应以单个服务进程运行，重启后原任务失效。
- 默认最多同时执行两个任务，解析限时 90 秒，下载限时 10 分钟，单文件上限 300 MB。完成文件默认保留 30 分钟，用户需及时保存。
- 截至 11 月 1 日，自动化测试 41 项通过。修改平台适配后，先运行项目测试，再用公开作品验证解析、实际下载、解码和网页保存；模拟响应无法替代实网验证。
- 若平台改版，先区分短链跳转、详情提取、媒体下载和文件处理哪个阶段失败。保持平台适配与下载流程分开，并保留作品 ID 校验，避免误下载推荐视频。
- 本版面向单个已发布视频，不支持图集、直播和批量列表。源码不包含虚拟环境、FFmpeg 可执行文件、下载产物或临时会话。第三方代码来源及许可见 [THIRD_PARTY.md](../THIRD_PARTY.md)。
